# Enums with Associated Values

## 目标

这个例子展示 Swift 枚举关联值如何表达有限状态和每种状态自己的数据。`CheckoutState` 不是用一组布尔值拼出结账流程，而是把“空购物车”“确认订单”“支付失败”“已支付”写成互斥的枚举 case，并让每个 case 携带它真正需要的信息。

学习重点是理解：枚举不是只能表示简单常量。Swift 的枚举可以把状态名称和状态数据绑定在一起，让非法组合更难出现。

## 特性说明

真实工程里经常有状态机：订单、登录、上传、同步、播放器、权限请求都只能处在有限几个阶段。若用多个可选字段和布尔值表达，例如 `isPaid`、`isFailed`、`orderID?`、`errorReason?`，就很容易产生矛盾状态：既支付成功又失败，或者失败了却没有失败原因。关联值枚举把每种状态需要的数据放进对应 case，`paymentFailed` 必须带失败原因，`paid` 必须带收据邮箱。

`describe(_:)` 使用 `switch` 拆解状态。Swift 会要求 `switch` 覆盖所有 case；当你以后新增一个状态时，编译器会提醒遗漏的处理逻辑。这对长期维护的业务流程很有价值，因为状态增加时，相关分支不会静悄悄漏掉。

如果不用枚举关联值，代码常会退化成字符串状态码加字典，或者一个对象里塞满 Optional 字段。那样虽然灵活，但调用方必须靠注释记住哪些字段在哪些状态下有效。Swift 的设计取舍是用类型把这些约束写出来。

## 设计取舍

关联值枚举的收益是状态互斥、数据贴近状态、模式匹配清晰。它特别适合有限且可枚举的领域状态。代价是当状态来自外部系统并且频繁变化时，你需要维护转换层；如果状态数量巨大或完全开放，枚举会变得笨重。

这个例子故意使用字符串和数组，保持关注点在语言特性上。真实项目中，`orderID`、邮箱、失败原因通常会进一步建成专门类型，避免把所有含义都压进 `String`。

## 运行

```bash
swift main.swift
```

## 观察点

- 输出会按流程打印四个互斥状态，没有任何对象同时处于“支付失败”和“已支付”。
- `reviewing` 可以携带可选优惠码，说明关联值里仍然可以组合 Optional，但 Optional 被限制在真正可能缺失的字段上。
- `switch` 中每个 case 都能直接绑定对应数据，不需要先检查一串布尔值再猜字段是否存在。
- 尝试注释掉一个 `case` 分支，编译器会提醒 `switch` 没有穷尽处理。

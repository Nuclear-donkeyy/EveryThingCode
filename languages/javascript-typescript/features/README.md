# JavaScript / TypeScript 特性与思想辅助教学

## 如何使用

先把这里当成语言思想地图，再进入每个例子目录运行 `node main.mjs`。这些例子只用 Node 标准能力和 JavaScript 运行时语义，不依赖 TypeScript 编译器；原因是学习边界要先看清楚：TypeScript 的类型在开发期帮助你表达和检查意图，但运行时真正执行的仍是 JavaScript。

建议每个例子跑两遍。第一遍只观察输出顺序和数据形状，第二遍修改一两行代码，例如调换 `await`、删除闭包里的私有变量、给输入 JSON 加一个错误字段，再看程序怎样变化。

## 思想总览

JavaScript 的核心思想是“动态对象 + 函数一等公民 + 事件驱动执行”。它最初服务浏览器交互，因此不能让一次网络请求或计时器阻塞整个页面；后来 Node 把同一套事件循环思想带到服务端，让大量 I/O 等待可以由单线程主执行流协调。TypeScript 没有替换这套运行时，而是在静态阶段给对象形状、函数参数和模块边界加上可推断的约束。

学习 JavaScript / TypeScript 时，要同时记住两条线：第一条是运行时线，关注对象、原型、闭包、模块、Promise、事件循环实际怎样执行；第二条是建模线，关注 TypeScript 怎样用结构化类型描述“这个值应当长什么样”。两条线交汇的地方最容易出错：例如 JSON 进入程序时只是运行时值，哪怕你在 TypeScript 里写了接口，也必须在边界做校验。

## 核心特性地图

### 事件循环与异步

它解决的问题是：在等待文件、网络、定时器这些慢操作时，不让主线程停住。JavaScript 采用事件循环，把同步调用栈、微任务队列和后续任务分开调度；Promise 的回调会在当前同步代码结束后尽快进入微任务阶段，计时器和 I/O 回调则等到对应阶段再运行。这种方式适合 I/O 密集应用，因为多数时间程序是在等待外部系统。

这门语言选择这种方式，是因为浏览器和 Node 都需要保持响应性，同时又希望普通业务代码不必直接管理线程锁。学习者应观察 `examples/event-loop-promises/`：它展示同步日志、Promise 微任务、`queueMicrotask`、`setTimeout` 和 `await` 的相对顺序。

### 原型/对象模型

它解决的问题是：对象需要共享行为，同时又要保持运行时灵活。JavaScript 没有把“类”作为唯一对象模型；对象可以通过原型链查找方法，`class` 只是更规整的语法外观。这样做的代价是 `this`、方法提取、属性遮蔽和原型修改都需要谨慎理解。

这门语言保留原型模型，是为了让对象字面量、函数、构造器和类都能落在同一套动态对象机制上。学习者可以在本页先理解这个模型，再回到根目录的 `examples/data-flow/` 对比对象字面量如何承载数据。这里的三个新增例子不专门写原型代码，但 `typed-data-shapes` 会展示对象“形状”在运行时仍要被检查。

### 模块与闭包

它解决的问题是：代码需要拆分文件，同时还要保留局部状态，避免所有变量挤到全局作用域。ES Module 给每个文件独立模块作用域，闭包让内部函数记住创建时的词法环境。两者组合后，可以写出“暴露少量函数，隐藏内部状态”的小模块。

JavaScript 使用词法作用域和一等函数，是因为函数既是行为单元，也是组合单元。学习者应观察 `examples/modules-closures/`：它在一个文件里模拟模块工厂，展示两个计数器如何共享同一套函数逻辑，却各自持有独立状态。

### TypeScript 的结构化类型思想

它解决的问题是：大型 JavaScript 项目里，函数和对象之间的契约只靠注释很容易漂移。TypeScript 用结构化类型描述值的形状：只要属性和方法匹配，名字不相同也可以兼容。这很适合 JavaScript 常见的对象字面量、渐进迁移和库生态。

这门语言选择结构化类型，而不是只按声明名义匹配，是为了贴合 JS 的实际写法。取舍是：类型看起来“能赋值”不代表数据一定来自可信来源，也不代表运行时会自动补字段。学习者应观察 `examples/typed-data-shapes/`：它用纯 JS 写出运行时校验，并在 README 中对应到 TypeScript 接口思维。

### 运行时值与静态类型边界

它解决的问题是：程序既要享受静态检查，又要面对网络、文件、环境变量、用户输入这些不可信值。TypeScript 类型在编译后会被擦除，运行时不会因为你写了 `User` 接口就自动拒绝坏 JSON；边界处必须用解析、校验或断言函数把 `unknown` 变成可信对象。

JavaScript / TypeScript 这样分工，是为了不改变 JS 运行时、保持生态兼容，同时给开发期提供足够强的反馈。学习者应观察 `examples/typed-data-shapes/`：它把原始 JSON 先当成未知值处理，再显式验证字段，最后才进入业务计算。

## 深入理解与对比练习

### 事件循环是“安排工作”的模型

JavaScript 的异步不是简单的“多线程”。事件循环把同步调用栈、微任务、定时器和 I/O 回调组织成可预测的执行顺序。学习 `event-loop-promises` 时，先预测每一行输出，再运行验证；然后把 `Promise.resolve().then(...)`、`setTimeout(...)` 和 `await` 的位置互换，观察输出顺序如何变化。这个练习能建立直觉：`await` 会暂停当前 async 函数，但不会冻结整个运行时。

### 闭包是状态边界，不只是面试题

闭包让函数记住创建时的词法环境，因此可以用来隐藏状态、构造工厂和实现模块级私有数据。它的风险是状态可能被长期持有，导致生命周期不清晰。学习 `modules-closures` 时，可以创建两个计数器实例，观察它们状态互不影响；再把状态改成全局变量，比较测试隔离和并发请求下的风险。

### 原型模型强调委托

JavaScript 对象不是从类复制出方法，而是通过原型链查找行为。`class` 语法让它看起来像传统类，但运行时仍然是原型委托。学习对象模型时，建议用 `Object.getPrototypeOf()` 观察方法在哪里，再思考为什么给实例动态加属性不会影响其他实例，而改原型方法会影响共享行为。这个模型解释了很多“为什么 this 变了”“为什么方法能被覆盖”的问题。

### TypeScript 保护的是开发期边界

TypeScript 的类型在编译后会消失，所以它不能替代运行时校验。它擅长让模块边界、函数输入和数据形状在开发期可见，减少重构时的隐式破坏。学习 `typed-data-shapes` 时，注意例子用 JS 运行，但文档讨论的是类型思想：真实项目中你会用 TypeScript 描述形状，再在 API 边界用运行时校验确认外部输入可信。

### 结构化类型既灵活也要克制

TypeScript 的结构化类型意味着“形状兼容即可赋值”，这非常适合前端数据组合和渐进迁移，但也可能让语义不同、字段相同的对象被误用。练习时可以设计 `UserId` 和 `ProductId` 都是字符串的场景，思考为什么需要 branded type 或封装对象。这个对比能帮助你理解：类型系统不只是检查字段，还要帮助表达业务含义。

## 学习检查

- 你能否解释为什么 `Promise.then` 往往早于 `setTimeout(..., 0)` 输出？
- 你能否说清楚闭包保存的是“变量绑定”而不是某个瞬间的拷贝？
- 你能否区分对象的运行时原型链和 TypeScript 的静态结构化类型？
- 你能否指出哪些数据已经在程序内部可信，哪些仍来自运行时边界需要校验？
- 你能否把一个例子的输入改坏，并说明错误是在静态阶段、运行阶段，还是人工观察阶段暴露的？

# Modules Closures

## 目标

用闭包模拟一个小模块：外部只能调用返回的函数，不能直接改内部变量。真实项目会把工厂函数、状态和导出拆到多个 ES Module 文件中；这里保持单文件，是为了让闭包捕获词法环境的过程更容易观察。

这个例子对应的语言特性是词法作用域、闭包和模块边界。真实工程中，组件状态、缓存、计数器、连接池、配置读取器都需要“内部可变、外部受控”的边界；如果不用闭包或模块作用域，代码很容易退化成全局变量，任何地方都能改，测试之间也会互相污染。

## 特性说明

`createCounter` 每次调用都会创建新的词法环境，其中的 `count` 和 `history` 只对返回对象里的方法可见。`increment` 和 `snapshot` 不是复制了一份数字，而是持续引用创建它们时那组变量绑定；所以多次调用 `increment` 会累积状态，而两个不同计数器之间不会串值。

ES Module 文件天然拥有模块作用域：文件里的顶层变量不会自动挂到全局对象。闭包则更细粒度，它让函数离开创建位置后仍能访问那里的局部变量。这个例子把两者压缩到单文件工厂函数里，是为了让学习者直接看到“共享函数结构”和“独立状态实例”的差别。

## 设计取舍

闭包的优势是封装简单，不需要额外类层级，也不需要约定命名来假装私有。它让模块可以暴露小而稳定的 API，把可变细节留在内部。代价是被闭包引用的对象会延长生命周期，如果闭包长期存在，里面的大数组、缓存或监听器也会被保留；因此真实项目要明确清理时机。

如果不用闭包，这个计数器可能会把 `count` 放到对象公开属性上，调用方随时能写 `pageViews.count = -999`。也可能把所有计数放进一个全局 Map，结果测试和并发请求共享状态。闭包不是唯一封装方式，但它是 JavaScript 中最轻量、最贴合函数一等公民思想的方式之一。

## 运行

```bash
node main.mjs
```

## 观察点

- `createCounter` 每调用一次，就创建一份新的词法环境。
- `increment` 和 `snapshot` 共享同一个 `count` 绑定，但外部代码拿不到这个变量。
- 两个计数器使用同一套函数结构，却不会互相污染状态。
- 这种“隐藏状态，只暴露操作”的方式，是模块化设计和闭包思想的交汇点。
- `direct count access undefined` 说明外部读取不到局部变量 `count`；它不是属性，而是闭包环境中的绑定。
- `snapshot` 返回的是拷贝后的 history 条目，学习者可以观察为什么外部修改快照不会直接改内部数组。

## 延伸练习

把 `let count = start` 移到 `createCounter` 外面，重新运行并比较两个计数器是否还隔离。再把 `snapshot` 改成直接返回 `history`，在外部 `push` 一条假记录，观察封装边界如何被破坏。

也可以给返回对象增加 `reset()` 或 `decrement()`，但不要直接暴露 `count`。这个练习的重点是练习 API 设计：外部需要表达意图，内部负责维护不变量，例如计数不能低于 0、历史记录必须按操作顺序追加。

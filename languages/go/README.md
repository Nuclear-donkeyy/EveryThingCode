# Go

## 语言定位

Go 的第一版学习基线是 **1.26.3**，工具链入口是 **Go 1.26.3**。它主要用于：云原生、微服务、CLI、基础设施。Go 的设计哲学是少语法、强工具链、默认并发、编译成单一可执行文件。它不追求表达力极限，而是强调团队协作中的可读性、构建速度和长期维护。

学习 Go 时不要只把它看作“带 goroutine 的 C”或“简化版 Java”。它的价值在工程默认值：`gofmt` 统一格式，`go test` 内置测试，标准库覆盖 HTTP、JSON、IO、加密、模板和上下文取消等常用能力。接口是隐式实现的，鼓励从使用者视角定义小接口。

## 适合场景

Go 适合稳定交付、部署简单、并发 IO 密集的系统：HTTP API、网关、后台任务、命令行工具、容器与 Kubernetes 生态、监控采集器、内部平台服务等。它的编译速度、静态链接和跨平台发布体验都比较轻。

Go 不太适合把类型系统当作主要建模工具的领域，也不适合对宏、函数式抽象或复杂泛型要求很高的代码风格。极致底层控制、强实时嵌入式、复杂数值计算或大量元编程场景，通常会更偏向 C/C++、Rust、Python 生态库或专用工具链。

## 核心语法

重点学习变量/常量、函数、模块、数据结构、泛型或类型标注、控制流，以及 Go 最常见的代码组织方式。变量声明有 `var`、短声明 `:=` 和常量 `const`，函数可以返回多个值，这也是错误处理的基础。控制流包括 `if`、`for`、`switch`、`select`，其中 `for` 同时承担 while 和传统循环角色。

Go 的复合类型包括 array、slice、map、struct。日常代码中最常用的是 slice、map 和 struct：slice 表达可变序列，map 表达键值索引，struct 表达业务数据。方法通过接收者绑定到类型上，接口用行为集合描述能力。惯用法包括：让零值可用、用小接口表达依赖、写表驱动测试、用 `defer` 管理关闭动作、用 `context.Context` 传递取消和超时信号。泛型主要用于容器、算法和减少重复。

## 类型/内存/并发模型

- 类型模型：静态类型、结构化接口、泛型。只要类型拥有接口要求的方法，就能作为该接口使用；这降低了耦合，也要求接口保持小而具体。
- 并发模型：goroutine、channel、context。goroutine 很轻量，但不是免费资源；channel 适合表达所有权转移、事件流和同步点，互斥锁适合保护共享状态。
- 内存与资源：Go 有垃圾回收，绝大多数对象由运行时管理。资源边界仍要显式处理，例如文件、网络连接、锁和取消函数。`defer f.Close()`、`defer cancel()` 是常见写法。性能敏感场景要用 benchmark 和 pprof 判断。

## 标准库与包管理

包管理入口：Go modules。一个模块由 `go.mod` 描述，依赖版本进入 `go.sum` 做校验。常用命令包括 `go mod init`、`go mod tidy`、`go test ./...`、`go run`、`go build`。第一版案例优先使用标准库，只有框架章节才引入生态依赖。

Go 标准库很实用：`net/http` 可直接写服务和客户端，`encoding/json` 处理 JSON，`io`、`os`、`path/filepath` 处理文件与流，`context` 管理请求生命周期，`testing` 和 `httptest` 支持测试。建议先掌握标准库风格，再看 Gin、Echo、Cobra、Zap、GORM 等生态库。

## 错误处理

Go 使用显式 `error` 返回，常见形式是 `value, err := fn()` 后立即判断。学习时关注错误如何被表达、传播、恢复，以及如何避免把异常路径藏在业务逻辑里。`fmt.Errorf("open config: %w", err)` 可以包装错误，`errors.Is` 和 `errors.As` 用于判断错误链中的类型或哨兵值。`panic` 不是常规错误处理机制，更适合不可恢复的程序员错误或启动阶段硬失败。

好的 Go 代码会在边界处补充上下文，在内部保留可判断的错误类型，在 API 层转换成合适的状态码或消息。配合 `defer` 可以确保错误路径下也能释放资源。

## 工程化

第一阶段关注代码格式、测试入口、依赖声明和可重复运行。`gofmt` 是强约束，`go vet` 能发现常见问题，`go test -race` 可检测数据竞争，benchmark 用 `go test -bench`。大型工程主题，如性能分析、发布、观测和安全，会在框架章节逐步展开。

项目组织上，简单服务可以从少量包开始，不必过早套复杂分层。常见目录包括 `cmd/` 放可执行入口，`internal/` 放只供本模块使用的实现，业务包按能力拆分。接口通常放在使用方一侧，以减少抽象泄漏。日志、配置、指标、数据库连接和 HTTP client 都应有清晰生命周期。

## 常见坑

- 只学习语法而忽略包管理和项目结构，导致看不懂 `go.mod`、`internal/` 和测试布局。
- 把其他语言的范式硬搬过来，例如到处建大接口、继承式层级或过度泛型，错过 Go 的小接口和组合风格。
- 忽略 `context` 取消，后台 goroutine 泄漏，channel 发送方和接收方生命周期不清晰。
- 在循环里误用变量地址或闭包捕获，尤其是并发启动 goroutine 时要确认每次迭代的值是否独立。
- map 并发读写没有加锁，测试偶尔通过但线上崩溃。
- 示例能跑但没有预期输出，导致无法判断自己是否真正理解。

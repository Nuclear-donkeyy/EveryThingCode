# C/C++ 基础语法速览

## 读者定位

这份速览面向已经写过其他编程语言、但第一次系统接触 C 或 C++ 的读者。你可能熟悉 Java、Go、Python、Rust、C# 或 JavaScript；迁移到 C/C++ 时，真正要补的不是 `if` 或 `for` 长什么样，而是“对象在哪里、能活多久、谁负责释放资源、编译器能帮我检查到什么程度”。

C 和 C++ 经常出现在同一章，但它们不是同一种语言的两个小版本。C 更接近可移植的系统接口语言：语法小、抽象少，强调内存布局、指针、头文件、ABI 和调用约定。C++ 兼容大量 C 语法，但它的日常心智模型是“静态类型 + 值语义 + RAII + 标准库容器 + 零成本抽象”。初学时可以把 C 看成底层边界和互操作基础，把现代 C++ 看成写大型性能程序的主力工具。

本章示例使用 C++23 和标准库。原因是 C++ 更适合用一个小程序同时展示字符串、容器、类、异常、可选值和资源管理；文档中会不断指出哪些概念属于 C，哪些属于 C++，以及混写时最容易误判的边界。

## 运行方式

C/C++ 通常需要先编译再运行。最小 C++ 程序的入口是 `int main()`，通过 `#include` 引入标准库声明，再由编译器和链接器生成可执行文件。示例目录中可以直接运行：

```bash
c++ -std=c++23 main.cpp -o /tmp/cpp-syntax-tour && /tmp/cpp-syntax-tour
```

`c++` 是常见的 C++ 编译器驱动命令，背后可能是 Clang、GCC 或其他实现。`-std=c++23` 选择语言标准；如果不写，编译器会使用默认标准，很多现代语法和库类型可能不可用。C 程序通常用 `cc -std=c23 file.c` 或具体的 `clang`、`gcc` 编译，入口同样是 `main`，但标准库、字符串和容器能力完全不同。

真实工程通常不会手写一长串编译命令，而是使用 CMake、Make、Ninja、Meson 或 IDE 工程生成构建。入门阶段先理解“预处理 include、编译每个源文件、链接成可执行文件”这条流水线，比记住某个构建工具的模板更重要。

## 语法速览

C/C++ 都使用花括号划分代码块，语句通常以分号结束。缩进不决定语义，但它决定代码是否容易审阅。`//` 是单行注释，`/* ... */` 是块注释。`#include <iostream>` 这类行不是普通语句，而是预处理指令：编译前把声明带入当前翻译单元。C 里常见 `#include <stdio.h>`，C++ 标准库头通常没有 `.h`，例如 `<string>`、`<vector>`、`<map>`。

`main` 是程序入口。现代 C++ 常写成 `int main()`，正常结束可以 `return 0;`，也可以让 `main` 走到末尾自动返回 0。命令行参数常写成 `int main(int argc, char* argv[])`。C 和 C++ 都有全局作用域、函数作用域和块作用域；C++ 还常用 `namespace` 给类型和函数分组，避免全局名字冲突。

变量声明写成“类型在前，名字在后”：`int count = 3;`。C++ 支持 `auto` 从初始化表达式推导局部变量类型，但这不是动态类型，推导完成后类型固定。`const` 表示这个名字不能再改，常用于配置、引用参数和防止误写；C++ 还提供 `constexpr` 表达编译期可求值。C 的 `const` 主要是只读约束，不等于一定是编译期常量。

C++ 的 `std::string`、`std::vector`、`std::map` 等标准库类型会自动管理资源，离开作用域时析构。C 没有这些容器，字符串通常是以 `'\0'` 结尾的 `char` 数组，动态内存通常靠 `malloc/free` 或平台 API 管理。把 C 的数组、指针和字符串约定直接搬到 C++ 业务代码里，往往会丢掉现代 C++ 最重要的安全网。

## 类型与值

基础类型包括 `bool`、`char`、整数类型如 `int`、`long long`、无符号整数如 `unsigned int`，以及浮点类型 `float`、`double`。不要默认假设所有平台上 `int` 或 `long` 宽度相同；需要精确宽度时使用 `<cstdint>` 中的 `std::int32_t`、`std::uint64_t` 等。布尔条件必须是逻辑含义清楚的表达式，虽然 C/C++ 允许不少隐式转换，但现代代码会避免依赖“非零即真”的暧昧写法。

C++ 字符串优先用 `std::string`，它知道自己的长度，能自动管理内存，也能和算法、容器一起工作。C 字符串是 `char*` 或 `char[]` 约定，长度常常需要另传，越界、缺少终止符和缓冲区不足是常见风险。跨 C API 时你会遇到 `c_str()`，它从 `std::string` 暴露一个只读 C 字符串视图；这个指针不能比原字符串活得更久。

指针和引用是 C++ 入门最容易混淆的部分。指针 `T*` 保存地址，可以为空，可以重新指向别处；引用 `T&` 是已有对象的别名，通常不能为空，也不能重新绑定。现代 C++ 里，普通参数优先按值或 `const T&` 传递；需要表达“可能没有对象”时用指针或 `std::optional`；需要表达所有权时优先用值、容器或智能指针，而不是裸 `new/delete`。

对象有生命周期。局部变量通常在栈上自动创建，离开作用域自动销毁；动态分配对象在 C 中要手动释放，在 C++ 中应交给 RAII 类型管理。RAII 的意思是资源获取即初始化：对象构造时拿资源，析构时释放资源。`std::vector` 释放动态数组，`std::string` 释放字符缓冲区，文件流关闭文件，锁对象释放互斥量。这个模型让错误路径和提前返回不再到处写清理代码。

## 控制流

`if` / `else` 与大多数 C 风格语言相似，条件放在圆括号里。C++17 以后可以在 `if` 里写初始化语句，例如 `if (auto value = find(); value) { ... }`，把临时变量作用域限制在分支附近。和 Python、JavaScript 不同，空集合不会自动当作 false；你应该明确写 `items.empty()` 或 `ptr != nullptr`。

`switch` 适合对整数、枚举或可转换为整型的值做分支。C 和 C++ 的传统 `switch` 默认会继续落入下一个 `case`，所以每个分支通常要写 `break`、`return` 或显式标注 `[[fallthrough]]`。这和 Go、C# 的默认不落入不同，是迁移时很常见的 bug 来源。

循环有三种常见形态：`for (int i = 0; i < n; ++i)` 适合索引，`while (condition)` 适合条件驱动，C++ 的范围 `for (const auto& item : items)` 适合遍历容器。遍历大对象时用 `const auto&` 避免拷贝；需要修改元素时用 `auto&`；只需要值副本时才用 `auto`。对 `std::map` 遍历得到的是键值对，C++17 起可以结构化绑定：`for (const auto& [key, value] : counts)`。

## 函数与模块

函数声明包含返回类型、函数名和参数列表：`int add(int a, int b)`。参数默认按值传递，函数拿到的是一份副本；传 `std::string`、`std::vector` 这类可能较大的对象时，读取用 `const T&`，需要接管或保存时再考虑按值并移动。返回局部对象通常直接按值返回，现代编译器会做返回值优化，没必要为了“省拷贝”返回悬垂引用或裸指针。

C 使用头文件声明接口、`.c` 文件定义实现；C++ 传统工程也大量使用 `.h/.hpp` 加 `.cpp`。`#include` 只是把声明文本带进来，不等于导入包。链接错误常常来自“声明看得见，但定义没有参与链接”。C++20 引入 modules，但现有生态仍以头文件为主，入门应先掌握 include guard、声明/定义分离和链接模型。

命名空间是 C++ 组织名字的主要方式。标准库放在 `std` 里，所以写 `std::vector`、`std::cout`。示例或小文件里可以局部使用 `using std::string;`，但头文件里不应写 `using namespace std;`，因为它会污染所有包含者的命名空间。C 没有 namespace，常通过函数名前缀模拟，例如 `sqlite3_open`。

C++ 支持函数重载、默认参数、模板和 lambda。它们很强，但基础阶段更重要的是写清楚参数所有权、返回值含义和错误策略。能用普通函数表达的逻辑不要急着模板化；能用标准库算法表达的遍历，也不必手写复杂宏。

## 集合与数据建模

C++ 常用集合包括 `std::vector<T>`、`std::map<K, V>`、`std::unordered_map<K, V>`、`std::array<T, N>` 和 `std::set<T>`。`vector` 是连续动态数组，适合大多数顺序列表；`map` 是按键有序的树形映射；`unordered_map` 是哈希表，通常查找更快但遍历顺序不稳定。C 没有标准泛型容器，常用数组加长度、结构体数组或项目自建容器。

数据建模从 `struct` 开始。C 的 `struct` 只是字段集合，函数通常放在外面并接收指针。C++ 的 `struct` 和 `class` 都可以有成员函数、构造函数和访问控制；默认差异是 `struct` 成员 public，`class` 成员 private。惯用上，简单数据载体用 `struct`，需要维护不变量、隐藏状态或管理资源时用 `class`。

引用、指针和容器会影响对象是否稳定。`vector` 扩容可能移动元素，使之前保存的元素指针或引用失效；`map` 的节点地址通常更稳定，但也有自己的迭代器规则。写 C++ 时不要只问“语法能不能编译”，还要问“这个引用指向的对象还活着吗，容器修改后它还有效吗”。

## 错误处理

C 常用错误码、空指针、返回长度、`errno` 或输出参数表达失败。调用方必须检查返回值，并在每个失败分支释放已经拿到的资源。C 代码里常见 `goto cleanup;` 并不一定糟糕，它常用于把清理路径集中到一个地方。

C++ 有异常，也有显式返回失败的类型。异常适合构造失败、I/O 失败、解析失败这类需要跨层传播的错误；`try` / `catch` 捕获后可以恢复、记录或转换边界。对于“查找不到”“字段缺失”这类正常分支，`std::optional<T>` 往往比异常更清楚。C++23 标准化了 `std::expected<T, E>`，用于返回成功值或错误值，但不同工具链支持进度可能不同；入门示例使用 `optional` 和异常保持可运行性。

RAII 是 C++ 错误处理的核心配套。只要资源由对象管理，异常抛出、早返回或循环中断时，析构函数都会自动执行。不要在异常可能经过的路径里依赖手写 `delete`、`close` 或 `unlock`；优先使用标准库对象、智能指针和作用域绑定对象。

## 惯用写法

现代 C++ 的第一条惯用写法是“能不用裸拥有指针就不用”。普通对象按值放在栈上或容器里，动态数组用 `std::vector`，文本用 `std::string`，可选值用 `std::optional`，唯一所有权用 `std::unique_ptr`，共享所有权只有在语义真实共享时才用 `std::shared_ptr`。裸指针仍有价值，但更适合表达非拥有、可空的观察关系。

第二条是 const 正确性。不会修改的对象用 `const`，不会修改参数的引用写 `const T&`，成员函数不修改对象时在末尾加 `const`。这让读者和编译器都能看见意图。与之配套的是短作用域：变量尽量在第一次需要时声明并初始化，不要先声明空对象再到处赋值。

第三条是优先标准库和清晰边界。遍历容器用范围 `for`，查找缺失用 `find` 或 `contains`，字符串拼接和格式化选择项目统一方式，排序用 `<algorithm>`。命名通常类型用 PascalCase 或项目风格，函数和变量用 snake_case 或 lowerCamelCase 取决于团队；标准库自身使用 snake_case。比命名风格更重要的是一致性和所有权表达。

最后，要尊重未定义行为。越界访问、悬垂引用、重复释放、有符号整数溢出、错误的类型别名都可能让程序“看似运行”但没有任何语言保证。打开编译警告，使用 sanitizer、静态分析和测试，是写 C/C++ 的基本卫生习惯。

## 可运行示例

本目录提供一个 C++23 标准库示例：

- [syntax-tour](examples/syntax-tour/)：用一个小型任务统计程序串起 `main`、`#include`、变量和常量、基础类型、`std::string`、`if` / `switch` / `for`、函数、`struct` / `class`、`std::vector` / `std::map`、引用和指针、命名空间、`std::optional`、异常以及 RAII 风格的作用域收尾。

运行：

```bash
cd languages/c-cpp/syntax/examples/syntax-tour
c++ -std=c++23 main.cpp -o /tmp/cpp-syntax-tour && /tmp/cpp-syntax-tour
```

示例刻意保持单文件，因为本章目标是理解语法组合，而不是先学习 CMake。读代码时可以先看 `main` 的主流程，再回到上方看 `demo` 命名空间里的类型和函数。

## 学习检查

读完后可以用这些问题自检：

- 你能说明 C 和 C++ 在字符串、容器、资源释放和错误处理上的默认心智差异吗？
- `#include`、声明、定义和链接分别解决什么问题？
- `const`、`auto`、引用和指针各自表达了什么约束？
- 为什么 `std::string` 和 `std::vector` 比 C 风格数组更适合现代 C++ 入门代码？
- `switch` 为什么需要小心 fallthrough？
- 什么时候用 `struct`，什么时候用 `class`？
- RAII 如何让异常和早返回路径仍然释放资源？
- 你能解释 `std::optional` 适合表达哪类失败，而异常适合表达哪类失败吗？
- 你能指出一段代码里谁拥有资源、谁只是借用对象吗？

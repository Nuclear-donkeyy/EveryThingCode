# generators-iterators

## 目标

用 `yield` 构建一个逐条产生日志行的生成器，理解 PHP 如何在不一次性构造完整数组的情况下处理数据流。这个例子适合学习文件读取、分页数据、批处理和 ETL 场景。

## 特性说明

生成器函数看起来像普通函数，但遇到 `yield` 时会暂停，把一个值交给调用方；下一次迭代时再从暂停处继续。它解决的是“大量数据不必一次性装进内存”的问题，也让数据处理可以表达成懒序列。

例子中的 `readEvents()` 模拟从日志源逐条读取事件，`importantEvents()` 只筛选需要关注的事件。调用方用 `foreach` 消费它们，不需要知道底层是数组、文件还是网络流。

## 设计取舍

数组适合小数据和需要随机访问的场景；生成器适合顺序处理、数据量大或来源昂贵的场景。生成器的代价是只能按顺序消费，不适合频繁回看前一个值，也不适合需要多次遍历同一批数据的逻辑。

生成器还会改变错误出现的位置：函数被调用时不一定立刻执行，真正迭代到某一步才可能抛出异常。真实项目中要在消费边界处理错误和清理资源。

## 运行

```bash
php main.php
```

## 观察点

- 输出只包含 `warning` 和 `error`，说明筛选发生在迭代过程中。
- `readEvents()` 没有返回数组，而是逐条 `yield`。
- `importantEvents()` 可以组合另一个生成器，形成轻量数据管道。
- 生成器适合顺序流，不适合需要随机访问的集合操作。

## 延伸练习

- 给事件增加 `debug` 级别，并确认它不会出现在输出中。
- 在 `readEvents()` 中加入一个非法事件，观察异常在何时抛出。
- 把生成器改成先构造完整数组，比较代码结构和内存心智模型。

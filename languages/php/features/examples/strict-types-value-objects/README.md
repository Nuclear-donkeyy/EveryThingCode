# strict-types-value-objects

## 目标

用 `declare(strict_types=1)`、参数类型、返回类型和只读属性构建一个 `Money` 值对象，观察 PHP 如何同时处理类型边界和领域不变量。这个例子不是为了证明 PHP 变成了静态语言，而是展示现代 PHP 如何把“输入形状错误”和“业务值非法”拆成两条清楚的防线。

## 特性说明

`strict_types=1` 作用在当前文件的函数调用边界上。没有它时，PHP 可能把字符串数字宽松转换成整数；有了它，`lineSubtotal(new Money(...), '2')` 会直接触发 `TypeError`。这说明类型声明负责的是“调用者传来的值是不是函数承诺的形状”。

`Money` 构造器里的检查负责另一层：`int $cents` 能保证金额是整数，却不能保证金额非负；`string $currency` 能保证货币代码是字符串，却不能保证它是三位大写代码。值对象的意义就是把这些不变量集中到创建阶段，让后续业务不必到处重复判断。

## 设计取舍

如果不用值对象，金额通常会退化成两个散落变量：`$priceCents` 和 `$currency`。这种写法短，但调用方可能把美元金额和人民币金额相加，也可能把负数传入折扣计算。值对象多了一层类型和构造成本，换来的是更稳定的业务边界。

`strict_types` 也不是万能校验。它无法判断字符串内容是否合法，无法替你做表单验证，也不会自动防止数据库中的脏数据。它更像一道函数边界的门禁：先挡住明显类型不对的值，再把领域规则交给对象或服务处理。

## 运行

```bash
php main.php
```

## 观察点

- `subtotal` 行说明合法数据可以顺利组合，调用方不需要关心金额格式化细节。
- `strict_types caught` 行说明字符串数量参数被函数签名拦截，而不是被悄悄转换。
- `value object caught` 行说明负金额不是类型错误，而是领域规则错误。
- `Money::multiply()` 返回新的 `Money`，没有修改原对象，便于把金额作为值传递。

## 延伸练习

- 去掉 `declare(strict_types=1)`，再运行例子，观察字符串 `'2'` 是否仍会被拦截。
- 给 `Money` 增加 `add(Money $other)`，并拒绝不同 currency 相加。
- 把 `Money` 改成裸数组 `['cents' => 1250, 'currency' => 'USD']`，比较调用方需要多写多少防御逻辑。

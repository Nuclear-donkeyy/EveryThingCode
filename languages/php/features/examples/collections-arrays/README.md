# collections-arrays

## 目标

观察 PHP array 既可以表示列表，也可以表示映射。例子先用数组处理购物车输入，再把稳定的业务概念转换成对象，说明“数组适合边界，对象适合核心”的取舍。学习重点不是记住 `array_map`，而是判断数据什么时候应该从松散结构进入稳定模型。

## 特性说明

PHP array 的弹性非常适合接收外部世界：请求参数、JSON、配置、数据库行都可以先被表示为数组。例子里的购物车原始数据就是一组关联数组，字段名来自外部输入，值也可能需要过滤和转换。

当数据进入核心逻辑后，继续使用关联数组会带来隐式约定：每个函数都要记住 `sku`、`qty`、`unitCents` 的拼写和含义。例子把有效行转换成 `CartLine` 对象，让字段、类型和计算方法聚在一起。这样后续聚合 subtotal 时，调用方依赖的是对象行为，而不是一堆字符串键。

## 设计取舍

数组的优势是轻、快、贴近输入；对象的优势是能命名概念、保护规则、承载行为。过早把所有输入都建成复杂类，会让简单脚本臃肿；长期把稳定业务都留在数组里，则会让项目变成“字符串键协议”的集合。

这个例子选择在过滤无效行之后再转换对象，是为了展示常见边界：外部输入可以脏，核心模型应该尽量干净。真实框架中，这个边界可能由 Request、DTO、Form、Validator 或 Serializer 完成。

## 运行

```bash
php main.php
```

## 观察点

- 输出中的有效商品已经排除了数量为 0 的行，说明边界处可以先做粗过滤。
- `CartLine` 的 `subtotal()` 把计算规则贴近数据，避免调用方重复写 `qty * unitCents`。
- 数组阶段适合处理外部形状，对象阶段适合表达稳定业务。
- 如果字段拼写错误，数组版本通常在运行时深处才出问题；对象构造能更早暴露。

## 延伸练习

- 新增一个缺少 `unitCents` 的原始行，观察当前代码会在哪里失败，并补上边界校验。
- 给 `CartLine` 增加 `currency` 字段，思考是否应该复用 `Money` 值对象。
- 把 `array_filter` / `array_map` 改成 `foreach`，比较哪种写法更适合加调试日志。

# Python

## 语言定位

Python 的第一版学习基线是 **3.14.5**，工具链入口是 **Python 3.14.5**。它主要用于：自动化、AI/数据、Web API、脚本工具。

Python 的设计哲学是“可读、直接、少惊喜”：用缩进表达结构，用简单语句组合复杂行为，用强大的标准库覆盖日常任务。它既能写一次性脚本，也能支撑大型服务、数据平台和机器学习工程。语言本身强调动态执行和快速反馈，生态则逐步补上类型标注、虚拟环境、打包、测试和格式化。学习 Python 不应只停留在“语法很简单”，更要理解它如何通过清晰命名、显式数据结构和成熟库把复杂问题拆小。

## 适合场景

- 自动化、数据处理、爬取、运维脚本和内部工具：代码短、标准库强、调试反馈快。
- AI、科学计算和数据工程：NumPy、Pandas、PyTorch、FastAPI 等生态使它成为事实上的胶水语言。
- Web API 和业务后台：适合中小到大型服务，尤其适合重 I/O、重集成、重迭代的团队。
- 不太适合极致低延迟、裸机资源控制或移动端原生核心逻辑；这些场景通常要借助 C/Rust/Go/Java 等组件。
- 不太适合没有工程约束的长期脚本堆积；动态类型和全局状态会让维护成本延后爆发。

## 核心语法

重点学习变量/常量、函数、模块、数据结构、泛型或类型标注、控制流，以及该语言最常见的代码组织方式。案例会尽量保持短小，让语法特征直接暴露出来。

Python 的日常语法围绕列表、字典、集合、元组、函数、类、模块和异常展开。惯用写法包括列表/字典推导式、迭代器、生成器、上下文管理器、`dataclass`、路径对象、关键字参数和小而清晰的函数。Python 没有真正的私有字段，约定比强制更多；因此命名、模块边界和测试比“隐藏实现”更重要。写 Python 时优先追求直白可读：复杂表达式可以拆成几行，中间变量常常比一行炫技更好。

## 类型/内存/并发模型

- 类型模型：动态类型，typing 提供渐进式类型。
- 并发模型：asyncio、线程、多进程。
- 内存与资源：结合语言自己的生命周期管理方式学习，不把所有语言都套成同一种范式。

Python 运行时仍是动态类型，变量名绑定到对象，对象带有自己的类型。`typing`、`mypy`、`pyright` 等工具提供开发期检查，适合在函数边界、数据模型和公共 API 上逐步增加标注。常见类型工具包括 `list[str]`、`dict[str, int]`、`Optional`/`| None`、`Protocol`、`TypedDict`、泛型和 `dataclass`。类型标注不是运行时验证，外部输入仍要解析和校验。

内存主要由引用计数和垃圾回收管理。多数对象会在引用计数归零时释放，但循环引用、缓存、生成器、闭包和全局单例仍可能延长生命周期。文件、锁、网络连接等资源要用 `with` 管理，避免依赖析构时机。并发方面，线程适合 I/O 等待，`asyncio` 适合大量网络连接和协作式任务，多进程适合 CPU 密集计算。学习时要理解 GIL 的影响：它限制同一解释器内多线程并行执行 Python 字节码，但不等于 Python 不能并发。

## 标准库与包管理

包管理入口：pip / uv / poetry。第一版案例优先使用标准库，只有框架章节才引入生态依赖。

标准库覆盖路径、文件、JSON、CSV、SQLite、HTTP、日志、时间、并发、测试和虚拟环境。很多学习案例可以只用 `pathlib`、`json`、`argparse`、`logging`、`unittest`、`venv` 完成。包管理要理解虚拟环境、依赖锁定、项目元数据和解释器版本。`pip` 是基础工具，`uv` 偏向快速统一的现代工作流，`poetry` 常用于应用和库的依赖声明与发布。不要把全局 Python 当项目环境，避免“我机器能跑”的隐性依赖。

## 错误处理

异常层级、上下文管理器、EAFP。学习时关注错误如何被表达、传播、恢复，以及如何避免把异常路径藏在业务逻辑里。

Python 鼓励 EAFP：先按正常路径执行，失败时捕获明确异常。`try/except/else/finally`、自定义异常、异常链和 `with` 是错误处理核心。捕获异常要窄，不要用裸 `except` 把问题吞掉；转换异常时保留 `from` 上下文；日志记录要带足输入、路径、外部系统状态等线索。对于可恢复错误，返回默认值或重试要有明确边界；对于程序员错误，应让它尽早暴露。

## 工程化

第一阶段关注代码格式、测试入口、依赖声明和可重复运行。大型工程主题，如性能分析、发布、观测和安全，会在框架章节逐步展开。

Python 工程通常以 `pyproject.toml` 为中心，配合虚拟环境、格式化、lint、类型检查和测试。常见工具包括 ruff、black、pytest、mypy/pyright、coverage 和 tox/nox。应用项目要关心配置、日志、迁移、任务队列、容器镜像和运行入口；库项目要关心包名、版本、公开 API、文档和兼容范围。保持导入方向清晰、避免模块执行副作用、让测试可以独立运行，是长期维护的关键。

## 常见坑

- 只学习语法而忽略包管理和项目结构。
- 把其他语言的范式硬搬过来，错过本语言的惯用表达。
- 示例能跑但没有预期输出，导致无法判断自己是否真正理解。
- 默认可变参数如 `def f(x=[])` 会在多次调用间共享状态。
- 混用项目环境和系统环境，导致依赖版本、解释器版本不可复现。
- 过度依赖动态字典传递业务数据，缺少边界模型和校验。
- 捕获所有异常后只打印一句话，丢失堆栈和错误上下文。
- 在 CPU 密集任务中期待线程线性加速，忽略 GIL 和进程/原生库方案。

- [hello](examples/hello/)：最小程序与运行方式，确认解释器、入口文件和输出。

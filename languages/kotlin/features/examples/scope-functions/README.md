# Scope Functions

## 目标

理解 Kotlin 作用域函数 `let`、`run`、`also`、`apply` 如何组织局部转换、对象配置和调试旁路。例子用请求参数构建搜索查询，展示每个函数适合承担的角色，并提醒过度嵌套会损害可读性。

这个例子对应 Kotlin 的 scope functions 思想：在一个临时作用域里操作对象，减少重复变量名，让转换、配置、校验和副作用更靠近相关数据。真实工程里，它们常见于输入清洗、构建 DTO、初始化配置对象、日志埋点和空安全链。

## 特性说明

`normalizeKeyword` 使用 `trim().takeIf { ... }?.let { ... }`，表示“只有关键字清理后仍有内容，才进入下一步转换”。`buildQuery` 用 `SearchQuery().apply { ... }` 配置一个可变对象，最后返回对象本身；这适合初始化或 builder 风格代码。随后 `.also { ... }` 打印调试信息，但不改变链路中的值。

`run` 用在 `query.run { ... }`，把对象作为接收者并返回代码块最后一个表达式，适合基于同一个对象计算摘要。通过这些差异可以记住一个实用规则：`let` 常用于把值命名为 `it` 后转换，`apply` 常用于配置并返回接收者，`also` 常用于旁路观察，`run` 常用于在接收者上下文里计算结果。

## 设计取舍

作用域函数的收益是让小范围逻辑更紧凑，尤其是空安全链和对象初始化。没有它们时，代码通常会出现很多临时变量、重复对象名和分散的日志语句。恰当使用时，读者能看到数据如何从输入一步步变成查询对象。

代价是它们太容易被嵌套滥用：`this`、`it` 混在一起后，代码会比普通变量更难读。真实项目中应优先让每个作用域函数只做一件事，复杂逻辑抽成命名函数；当你需要解释某个 `it` 到底是谁时，往往说明该拆开了。

## 运行

```bash
kotlin main.kts
```

## 观察点

- 空白关键字会被 `takeIf` 过滤，因此返回默认查询词。
- `apply` 块里可以直接写 `keyword = ...`、`pageSize = ...`，最终返回配置好的 `SearchQuery`。
- `also` 会打印调试行，但链路继续传递同一个查询对象。
- `run` 输出摘要字符串，说明它更适合“在对象上下文里计算另一个结果”。

## 延伸练习

- 把 `also` 中的打印改成收集审计事件列表，思考副作用是否仍然足够清楚。
- 新增 `sort: String?` 输入，用 `let` 只接受 `"newest"` 或 `"popular"` 两种值。
- 故意嵌套两个 `apply`，观察 `this` 指向是否变得难懂，再尝试拆成命名函数。

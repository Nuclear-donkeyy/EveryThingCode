# Kotlin 特性与思想辅助教学

## 如何使用

本模块适合在读完 Kotlin 根目录的基础介绍后使用。建议先打开一个例子目录，阅读 `README.md` 的目标和观察点，再运行 `kotlin main.kts`，最后回到本页把输出和语言设计联系起来。

这些例子都使用 Kotlin 脚本和标准库，不依赖 Gradle 或第三方库。这样做的目的不是回避真实工程，而是先把语言本身的表达方式看清楚：类型如何约束空值，状态如何穷尽，函数如何贴近业务词汇，异步思想如何从“生命周期和边界”开始理解。

## 思想总览

Kotlin 的很多特性不是为了把代码写得更短，而是为了把工程里容易出错的事情提前变成类型、结构和局部规则。空值不再只是运行时约定，而是 `String` 与 `String?` 的类型差异；业务结果不必散落在异常和魔法字符串里，而可以用 `sealed class` 或 `sealed interface` 明确列出；对象传输不必手写比较、打印和拷贝样板，而由 `data class` 把“这是数据”表达出来；集合处理不必总是手写循环，而可以用标准库函数表达数据流；局部转换、对象配置和旁路调试可以通过作用域函数保持在小范围内；领域表达不必总是塞进工具类，而可以用扩展函数和带接收者的 lambda 形成小型 DSL。

学习 Kotlin 时要特别关注取舍。空安全要求你在边界处认真处理缺失值，但换来调用链里的可见性；`data class` 生成很多便利方法，但也提醒你不要把可变集合随意塞进看似不可变的数据里；sealed 层级让 `when` 可以穷尽检查，但适合有限状态，不适合无限扩展的插件体系；集合链能提高表达力，但要理解普通集合和 `Sequence` 的求值时机；作用域函数能减少重复变量名，但嵌套过度会让 `it` 与 `this` 变成负担；扩展函数能改善 API 阅读体验，但它不会真的修改原类型，也不应该隐藏复杂副作用；协程让异步流程接近顺序阅读，但真正的重点是结构化并发、取消传播和资源归属，而不是“启动很多任务”。

## 核心特性地图

### 空安全

它解决的问题是空指针错误太容易从一个边界传播到很深的调用栈。Kotlin 把可空性放进类型系统：非空类型不能直接接收 `null`，可空类型必须通过 `?.`、`?:`、`let`、`takeIf`、智能类型转换等方式处理后才能使用。这样会让代码在输入边界稍微啰嗦一点，但能把“这个值可能不存在”保留在签名和调用点上。

学习者应该观察 `examples/null-safety/`：同一批用户资料里有缺失昵称、空白昵称和缺失邮箱，脚本会用安全调用和 Elvis 运算符给出可读的兜底结果，而不是使用 `!!` 把风险推迟到运行时。

### data class

它解决的问题是数据载体常常需要相等性、可读打印、解构和复制，而手写这些样板既重复又容易漏字段。Kotlin 用 `data class` 声明“这个类型主要表示值”，编译器据此生成 `equals`、`hashCode`、`toString`、`copy` 和 `componentN`。这种方式强调数据建模本身，而不是让类文件被样板淹没。

学习者应该观察 `examples/data-classes-copy/`：工单状态通过 `copy` 从旧值派生新值，输出中的结构化文本、按值比较和解构都来自 data class 的生成能力。例子最后还故意展示浅拷贝风险，提醒学习者不要把 `val` 和深度不可变混为一谈。

### sealed class / sealed interface

它解决的问题是业务状态有限但分散表达时，调用方很难知道是否处理完整。例如支付结果可能成功、拒绝、需要人工审核；如果用字符串或整数码，新增状态时很容易漏改。Kotlin 的 sealed 层级把所有直接子类型限制在可控范围内，`when` 表达式可以检查是否穷尽。

学习者应该观察 `examples/sealed-results/`：`CheckoutResult` 列出三类结果，打印摘要的 `when` 没有 `else`。这让读者能看到 Kotlin 如何把“未来维护者必须处理每种结果”变成编译期压力。

### 集合函数与 Sequence

它解决的问题是业务数据处理很容易被循环、临时变量和手动累计淹没。Kotlin 标准库为集合提供 `filter`、`map`、`groupBy`、`sumOf`、`partition` 等函数，让代码更接近“筛选已支付订单、映射收入条目、按地区汇总”这样的业务描述。普通集合链默认立即求值，每一步通常会产生中间集合；`Sequence` 则把转换组成惰性流水线，到终端操作才逐个推进。

学习者应该观察 `examples/collections-sequences/`：同一批订单先用普通集合链做收入汇总，再用 `asSequence()`、`take(2)` 和调试输出展示惰性求值。这个例子要看的不是“Sequence 永远更快”，而是 Kotlin 给了你在可读性和求值策略之间切换的工具。

### 作用域函数

它解决的问题是局部转换、对象初始化和旁路观察经常需要重复变量名，导致代码很吵。Kotlin 的 `let`、`run`、`also`、`apply`、`with` 都是在一个临时作用域里操作对象，但返回值和接收者规则不同：`let` 常用于转换，`apply` 常用于配置并返回对象，`also` 常用于调试或审计旁路，`run` 常用于在接收者上下文里计算另一个结果。

学习者应该观察 `examples/scope-functions/`：脚本用 `let` 清洗关键字，用 `apply` 配置查询对象，用 `also` 打印调试信息，用 `run` 生成摘要。学习重点是为每个函数分配清楚角色，而不是把所有逻辑都压进一条嵌套链。

### 扩展函数与 DSL 思维

它解决的问题是通用类型或外部类型经常缺少领域词汇，而继承或工具类又会让调用代码变得绕。Kotlin 的扩展函数允许在不修改原类型的前提下，为某个类型添加更贴近业务的调用方式；带接收者的 lambda 则能让一段配置代码像在某个上下文里直接说话。

学习者应该观察 `examples/extensions-dsl/`：脚本定义 `checklist { task(...) { ... } }`，并给 `List<Task>` 增加 `ownedBy`、`totalMinutes` 这类领域操作。要注意扩展函数是静态解析的语法能力，不是 monkey patch；好的 DSL 应该让边界更清楚，而不是把副作用藏起来。

### 协程思想

它解决的问题是异步任务、取消、超时和资源生命周期在回调或裸线程里容易失控。Kotlin 的协程把“可挂起的计算”写成接近顺序的代码，并通过结构化并发要求子任务属于某个作用域。真实项目通常会使用 `kotlinx.coroutines`、`Flow` 和平台 scope，例如 Android 的 `viewModelScope` 或服务端请求 scope。

本模块不引入外部依赖，因此例子优先展示标准库脚本中的顺序数据流和显式结果边界：先用 `examples/sealed-results/` 理解结果如何被类型表达，再用 `examples/extensions-dsl/` 理解“在上下文中顺序描述流程”的阅读体验。之后再学习 `suspend`、`coroutineScope`、取消传播和调度器，会更容易区分语言思想与生态库 API。

## 深入理解与对比练习

### Kotlin 的目标是减少“无意义的防御代码”

Kotlin 继承了 JVM 生态，又试图减少 Java 项目里常见的样板代码和空指针防御。`val`、空安全、data class、sealed class、扩展函数和协程都服务于同一个方向：让业务意图更集中，错误边界更显性。学习时不要只比较“少写多少行”，而要观察哪些约定从注释、运行时异常或代码评审变成了类型和语法。

### 空安全把不确定性推到入口

`String?` 和 `String` 的区别迫使你在数据进入系统时处理未知，而不是把 `null` 传到深层逻辑。学习 `null-safety` 时，可以把可空输入直接传给需要非空的函数，观察编译器如何阻止；再使用 Elvis 操作符、早返回或 `requireNotNull` 表达不同处理策略。这个特性不是让代码没有 null，而是让 null 的传播路径可见。

### data class 与 sealed class 分别表达“数据”和“状态集合”

`data class` 适合值对象，自动提供复制、相等性和解构；`sealed class` / `sealed interface` 适合有限状态。学习 `data-classes-copy` 时，可以把字段改成可变集合，观察浅拷贝如何影响快照语义；学习 `sealed-results` 时，可以新增一个结果分支，观察处理函数是否需要更新。这些练习非常接近真实业务：UI state、登录、支付、审批、网络请求都不是随便一个字符串，而是一组有结构的数据或有限且有载荷的结果。

### 集合链、Sequence 和作用域函数都在管理“局部复杂度”

集合函数把循环细节藏到标准库里，让读者关注数据转换；`Sequence` 把中间集合成本延后到终端操作；作用域函数把对象相关操作收进小块上下文。学习时可以把 `collections-sequences` 的 `asSequence()` 去掉，比较输出顺序；再把 `scope-functions` 改成普通临时变量写法，判断哪一种更容易读。Kotlin 给这些工具不是为了追求链式写法，而是为了在合适边界内减少噪声。

### 扩展函数是局部语言，不是猴子补丁

扩展函数看起来像给类型加方法，但它是静态解析的语法便利，不能真正修改原类。它适合把领域表达贴近调用点，例如 `order.total()`、`String.normalized()`；不适合把大量业务逻辑藏到到处可见的扩展里。学习 `extensions-dsl` 时，观察 DSL 如何让配置更像领域语言；再思考过度 DSL 会不会让跳转和调试变难。

### 协程思想是结构化任务生命周期

即使当前例子优先标准库脚本，Kotlin 的并发学习也应记住：协程的价值不是“更轻的线程”这句口号，而是把任务启动、取消、父子关系和异常传播放进结构化作用域。后续进入 Ktor 或 Android 时，你会反复遇到 scope、Job、Flow。现在可以先用 sealed 结果和扩展 DSL 打好基础：异步任务最终也需要明确结果类型和清晰边界。

## 教学例子索引

- [null-safety](examples/null-safety/)：用可空类型、安全调用和兜底值处理不完整输入。
- [data-classes-copy](examples/data-classes-copy/)：用 data class 的生成方法、`copy` 和解构表达值对象状态演进，并观察浅拷贝边界。
- [sealed-results](examples/sealed-results/)：用 sealed 层级和 `when` 穷尽检查表达有限业务结果。
- [collections-sequences](examples/collections-sequences/)：用集合函数表达报表数据流，并用 `Sequence` 观察惰性求值和短路处理。
- [scope-functions](examples/scope-functions/)：用 `let`、`apply`、`also`、`run` 组织输入清洗、对象配置、旁路调试和摘要计算。
- [extensions-dsl](examples/extensions-dsl/)：用扩展函数和带接收者 lambda 组织小型领域 DSL。

建议按上面的顺序学习。第一步先看类型如何阻止空值误用，第二步看 data class 如何表达值对象，第三步看状态如何被枚举和分发，第四步比较集合链与惰性流水线，第五步掌握局部作用域工具，最后看 Kotlin 如何把普通函数组合成更贴近领域的读法。

## 学习检查

- 看到 `String?` 时，能否说出调用者必须多做哪一步？什么时候应该返回空值，什么时候应该返回 sealed 结果？
- 能否解释 `data class` 的 `copy` 是浅拷贝，为什么这会影响含有可变集合的模型？
- 给 `CheckoutResult` 新增一种状态时，哪些 `when` 会被编译器提醒？这比字符串状态码可靠在哪里？
- 普通集合链和 `Sequence` 的求值时机有什么差异？什么时候可读性比惰性更重要？
- `let`、`apply`、`also`、`run` 的返回值和适用场景有什么不同？什么时候应该拆成命名函数？
- 扩展函数为什么不能访问被扩展类型的私有成员？这说明它和继承、真正修改类有什么区别？
- 学完标准库脚本后，再看协程时能否先问清楚：任务属于哪个 scope，失败是否取消兄弟任务，结果如何回到调用方？

# Rust 特性与思想辅助教学

## 如何使用

这个模块不是新的语法清单，而是把 Rust 的几个核心思想放到可运行代码旁边看。建议先读下面的“思想总览”和“核心特性地图”，再进入每个例子目录运行 `main.rs`。运行时不要只看输出，还要尝试改动代码：去掉 `&`、把不可变借用改成可变借用、漏掉一个 `match` 分支、把 trait 泛型改成具体类型、让线程闭包不使用 `move`。Rust 的编译错误通常就是教学材料的一部分，它会指出“数据归谁所有”“这里能不能共享”“失败有没有被处理”“跨线程的数据是否安全”。

所有例子都只使用标准库，可以用 `rustc` 直接编译。真实项目中通常会用 Cargo 管理包、测试和依赖，但这里刻意保持单文件，是为了让注意力集中在语言设计本身。推荐顺序是：先看所有权与借用，再看生命周期；随后学习 enum、Result 和模式匹配；最后进入 trait、迭代器和线程 channel，把“类型约束”和“数据流”放到更接近工程的场景里观察。

## 思想总览

Rust 的中心取舍是：把一部分灵活性提前交给编译器检查，换取运行时更少的隐藏状态。它没有垃圾回收器，也不希望程序员手动 `free` 每一块资源，所以用“所有权”决定资源何时释放；它不把空值和异常作为默认控制流，所以用 `Option` 和 `Result` 把“不存在”和“失败”写进类型；它希望抽象不必牺牲性能，所以用 trait、泛型和单态化让许多抽象在编译期展开；它也希望并发错误尽早暴露，所以用 `Send`、`Sync` 这类标记 trait 约束跨线程移动和共享。

学习 Rust 时，最重要的不是背规则，而是形成问题意识：这个值的负责人是谁？当前代码只是读取还是要修改？失败路径是否被调用方看见？抽象之后机器实际执行的工作有没有增加？一旦这些问题成为直觉，Rust 的严格性会从阻力变成设计反馈。

## 核心特性地图

### 所有权与借用

它解决的问题是内存释放、悬垂引用和数据竞争。传统系统语言常把资源生命周期交给程序员手动维护，灵活但容易出错；GC 语言则把释放时机交给运行时，简单但成本和时机不完全可控。Rust 选择让每个值有唯一所有者，所有者离开作用域时自动释放；临时访问用借用表达，`&T` 读取，`&mut T` 独占修改。学习者应该观察 `examples/ownership-borrowing/`：同一个库存列表可以被不可变借用查看，也可以在没有其他活跃借用时被可变借用更新。

### 生命周期直觉

生命周期解决的问题是“引用不能比被引用的数据活得更久”。Rust 大多数时候能自动推断生命周期，初学者不必急着写复杂标注。真正要建立的是直觉：返回引用时，返回值一定来自某个输入或长期存在的数据；如果局部变量马上销毁，就不能把指向它的引用交出去。Rust 用生命周期参数描述引用之间的关系，而不是延长对象本身的生命。学习者应该观察 `examples/lifetimes-references/`：结构体持有字符串切片，函数在多个输入引用之间选择返回值，标注表达的是“返回值从哪里来”。

### enum、Result 与 Option

它们解决的问题是状态分支、空值和可恢复失败。许多语言把 `null`、异常和状态码混在一起，调用者可能忘记检查。Rust 用 `enum` 表达“一个值只可能处于这些形态之一”，用 `Option<T>` 表达可能没有值，用 `Result<T, E>` 表达可能失败，并通过 `match` 逼迫调用方覆盖所有分支。这种方式让业务状态成为类型的一部分。学习者应该观察 `examples/enums-result/`：解析输入、判断状态、处理缺失值都不需要隐藏异常。

### 模式匹配与结构化分支

模式匹配解决的问题是“分支逻辑不仅要判断条件，还要拆开数据结构”。在很多语言里，命令处理、协议解析和状态机代码容易退化成字符串比较、数组下标和多层 `if`。Rust 的 `match` 可以匹配 enum 变体、结构体字段、元组值、切片形状和额外 guard，并要求分支穷尽。Rust 为什么把它做成核心语法？因为 enum 和 `match` 合在一起能让状态空间保持封闭：新增状态时，编译器会指出哪些处理逻辑没有更新。学习者应该观察 `examples/pattern-matching/`：文本命令先被解析成 `Command`，再通过模式拆解和执行。

### trait 与零成本抽象

trait 解决的问题是“不同类型共享一组能力，但不想丢掉静态类型信息”。Rust 的泛型函数可以要求类型实现某个 trait，编译器再为实际使用到的类型生成具体代码，这常被称为零成本抽象：源代码保留抽象，运行时通常不需要额外的动态查找。当然，trait object 也可以做动态分发，适合需要异构集合或插件边界的场景。学习者应该观察 `examples/traits-iterators/`：任务类型实现 trait 后，可以被通用函数和迭代器链处理。

### 迭代器与集合数据流

迭代器解决的问题是集合处理如何保持可组合、惰性和类型安全。命令式循环当然可用，但当筛选、映射、聚合、查找混在一起时，循环里的临时变量和状态更新容易掩盖业务意图。Rust 的迭代器把“从哪里来”“保留哪些”“变成什么”“在哪里消费”拆成一串明确操作，许多适配器在被 `collect`、`sum`、`max_by_key` 等消费前不会真正执行。学习者应该观察 `examples/traits-iterators/`：评分任务先经过 `filter` 和 `map`，再收集成摘要列表，同时 `best_item` 使用迭代器查找最高分。

### 并发安全与 Send/Sync 思想

它解决的问题是跨线程移动、共享和修改数据时的安全边界。Rust 不把“能在线程间传递”当成默认事实，而是用 `Send` 表示所有权可以移动到另一个线程，用 `Sync` 表示共享引用可以安全地被多个线程使用。多数基础类型会自动获得这些能力；包含非线程安全内部状态的类型则不会。Rust 为什么这样做？因为数据竞争不是运行慢一点的问题，而是可能导致未定义行为的问题。所有权和借用规则先限制别名与修改，再由 `Send`/`Sync` 把限制延伸到线程边界。学习者应该观察 `examples/threads-channels/`：工作线程通过 `move` 获得输入数据，再把 `Reading` 消息发送给主线程，避免共享可变集合。

## 深入理解与对比练习

### 所有权是在编译期写下资源协议

Rust 的所有权规则不是为了为难初学者，而是把“谁负责释放、谁可以修改、谁还能读取”提前到编译期确认。学习 `ownership-borrowing` 时，重点观察值被移动后为什么不能再用、可变借用为什么必须独占。然后尝试把一个函数从接收所有权改成接收引用，思考调用方还能否继续使用原值。这个练习能把“编译器报错”转化成资源生命周期的反馈。

### 生命周期多数时候是推断出来的

生命周期标注不是让对象活得更久，而是描述引用之间的有效关系。很多日常代码无需手写生命周期，因为编译器能推断；当函数返回引用或结构体持有引用时，才需要显式说明。阅读例子时，可以先避免返回借用，改成返回拥有所有权的数据；再比较性能和清晰度。Rust 的一个关键取舍是：宁愿在 API 边界多写一点，也不让悬垂引用进入运行时。

### enum 把失败和状态变成数据

`Option` 和 `Result` 让“没有值”和“失败原因”成为类型的一部分，而不是隐藏在异常或空指针里。学习 `enums-result` 时，注意调用方必须处理 `Ok` 和 `Err`。可以新增一个错误类型，例如 `PermissionDenied`，再观察匹配分支如何逼迫你讨论业务后果。这个反馈让领域状态从注释变成可检查的代码。

### 模式匹配让状态处理回到数据形状

学习 `pattern-matching` 时，注意 `match` 的分支不是随意排列的字符串判断，而是对数据形状的声明。你可以新增 `Resize`、`Rotate` 或 `Undo` 命令，看编译器如何要求执行逻辑覆盖新状态。也可以把解析失败从默认写入命令改成 `Result<Command, String>`，比较“未知命令也是数据”和“未知命令是错误”两种建模方式。

### trait 是行为约束，不是继承树

Rust 的 trait 描述类型能做什么，并通过泛型或 trait object 在编译期/运行期形成不同分发方式。学习 `traits-iterators` 时，观察同一个函数如何接收满足 trait 的不同类型；再比较静态分发的泛型和动态分发的 `Box<dyn Trait>`。这能帮助你理解“零成本抽象”不是没有抽象，而是很多抽象在编译后不额外付运行时成本。

### 并发安全来自类型边界

Rust 不会让数据竞争靠约定避免。`Send`、`Sync`、所有权移动、锁和 channel 一起表达线程间共享规则。学习 `threads-channels` 时，观察 `move` 闭包如何把数据交给线程，channel 如何把消息所有权交回主线程。再把实现改成 `Arc<Mutex<Vec<Reading>>>`，比较共享内存和消息传递的差异。学习目标不是背这些类型，而是理解：并发设计必须先回答所有权和共享边界。

## 学习检查

- 看到一个变量时，能说出它是拥有数据，还是只是借用了数据。
- 看到函数签名时，能判断调用者是否还保留原值，是否允许函数修改它。
- 遇到可能缺失或失败的操作时，优先想到 `Option` 或 `Result`，而不是隐藏状态码。
- 写 `match` 时，能解释每个分支对应的业务状态，而不是只为了让编译器安静。
- 使用 trait 泛型时，能说清楚它抽象的是能力，不是继承层级。
- 看到 `match` 时，能区分它是在判断普通条件，还是在拆解 enum、元组、结构体或切片的数据形状。
- 讨论并发时，能把问题拆成“移动所有权”“共享只读引用”“共享可变状态”三类，再选择 `thread`、channel、`Arc`、`Mutex` 等工具。

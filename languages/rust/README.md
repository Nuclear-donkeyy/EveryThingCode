# Rust

## 语言定位

Rust 的第一版学习基线是 **1.96.x**，工具链入口是 **Rust stable**。它主要用于：系统编程、性能服务、嵌入式、WebAssembly。Rust 的核心目标是在没有垃圾回收的前提下提供内存安全和并发安全，同时保持接近 C/C++ 的性能上限。它把资源所有权、生命周期和错误传播显式纳入类型系统，让许多问题在编译期暴露。

Rust 适合愿意用更严格的编译器换取长期可靠性的项目。借用检查器会强迫你说明：谁拥有数据，谁只是临时读取，谁可以修改，资源何时释放。掌握这些规则后，Rust 代码具有很强的局部可推理性。

## 适合场景

Rust 适合性能敏感、可靠性要求高、资源边界复杂的场景：命令行工具、网络服务、数据库组件、编译器、浏览器/渲染引擎模块、区块链基础设施、嵌入式、WebAssembly 和安全关键的系统库。它也适合替换部分 C/C++ 模块，用更强的类型约束减少未定义行为。

Rust 不一定适合快速试错的脚本、小型一次性自动化、团队完全没有系统语言经验且交付周期极短的项目。它的学习曲线主要来自所有权、生命周期、trait、异步运行时和生态选择。Rust 会把许多运行时或代码审查中才暴露的问题提前到编译期，初学阶段会慢一些，但重构和并发扩展更安心。

## 核心语法

重点学习变量/常量、函数、模块、数据结构、泛型或类型标注、控制流，以及 Rust 最常见的代码组织方式。Rust 默认变量不可变，使用 `mut` 才能修改；表达式可以产生值，因此 `if`、`match`、代码块都能参与赋值。函数签名通常明确写出参数和返回类型，编译器在局部变量处提供强类型推断。

核心数据结构包括 tuple、array、slice、struct、enum。`enum` 与 `match` 是 Rust 建模能力的关键，`Option<T>` 表示可能为空，`Result<T, E>` 表示可能失败。模块由 `mod`、`use`、`pub` 组织，crate 是编译和发布单元。惯用法包括：优先用不可变数据，使用 `match` 穷尽处理状态，用迭代器链表达集合转换，用 `impl` 组织类型方法，用 trait 抽象能力，用 `derive` 自动生成常见行为。

## 类型/内存/并发模型

- 类型模型：静态类型、代数数据类型、trait。Rust 的类型系统能表达“这个值可能不存在”“这个操作可能失败”“这个能力由哪些类型实现”。trait 类似接口但更强，可配合泛型、关联类型和 trait object 使用。
- 并发模型：所有权、Send/Sync、async runtime。所有权规则让跨线程共享和转移更明确，`Send` 表示可移动到其他线程，`Sync` 表示可被多线程共享引用。异步代码使用 `async`/`await`，但真正调度任务需要 Tokio、async-std 等运行时。
- 内存与资源：Rust 没有 GC，资源在所有者离开作用域时自动释放。RAII、`Drop`、借用和生命周期共同决定资源边界。`Box` 管理堆分配，`Rc`/`Arc` 表达引用计数，`RefCell`/`Mutex` 把检查移动到运行时或线程同步层。

## 标准库与包管理

包管理入口：Cargo。`Cargo.toml` 描述包、依赖、feature 和构建配置，`Cargo.lock` 锁定应用依赖版本。常用命令包括 `cargo new`、`cargo run`、`cargo test`、`cargo fmt`、`cargo clippy`、`cargo build --release`。第一版案例优先使用标准库，只有框架章节才引入生态依赖。

标准库提供集合、迭代器、文件 IO、线程、同步原语、时间、路径和基础网络能力，但很多高层能力由 crate 提供，例如 serde 处理序列化，tokio 支持异步网络，clap 构建 CLI，anyhow/thiserror 改善错误建模。学习顺序建议先读懂 `Option`、`Result`、Iterator、String/str、Vec/slice。

## 错误处理

Rust 的错误处理以 `Result`、`Option`、`?`、panic 边界为核心。`Option<T>` 表示无值不是异常，`Result<T, E>` 表示可恢复失败，`?` 用于在当前函数返回兼容错误类型时提前传播。学习时关注错误如何被表达、传播、恢复，以及如何避免把异常路径藏在业务逻辑里。

库代码通常应返回清晰的错误类型，应用层可以使用更宽松的错误封装来聚合上下文。`panic!` 适合不可恢复的逻辑错误、测试断言或启动时硬失败，不应替代普通错误返回。好的错误设计会让调用方知道哪些失败可重试，哪些失败要提示用户，哪些是程序不变量被破坏。

## 工程化

第一阶段关注代码格式、测试入口、依赖声明和可重复运行。`rustfmt` 统一格式，`clippy` 提供静态建议，`cargo test` 同时支持单元测试、集成测试和文档测试。大型工程主题，如性能分析、发布、观测和安全，会在框架章节逐步展开。

Rust 项目通常把库逻辑放在 `src/lib.rs`，可执行入口放在 `src/main.rs` 或 `src/bin/`。模块边界要围绕领域能力设计，公开 API 使用 `pub` 精确暴露。CI 中常见检查是 `cargo fmt --check`、`cargo clippy -- -D warnings`、`cargo test`。性能优化应先 benchmark，再考虑分配次数、拷贝、锁竞争和异步任务调度。

## 常见坑

- 只学习语法而忽略包管理和项目结构，导致看到 workspace、feature、crate 边界时无从下手。
- 把其他语言的范式硬搬过来，例如试图到处共享可变对象，而不是重新思考所有权和数据流。
- 为了绕过借用检查器滥用 clone、Rc、RefCell 或 Arc<Mutex<T>>，短期能编译，长期会让性能和可读性变差。
- 混淆 `String`、`&str`、`Vec<T>`、`&[T]` 的拥有与借用关系。
- 在 async 代码中持有锁跨越 `.await`，造成死锁或吞吐下降。
- 示例能跑但没有预期输出，导致无法判断自己是否真正理解。

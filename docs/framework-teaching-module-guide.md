# 框架教学模块编写规范

本规范用于统一 `frameworks/<language>/` 下的框架章节。读者假设为已经会编程、了解 HTTP/UI/构建系统等基础概念，但没有系统使用过该语言生态下的框架。

## 语言框架索引

每个语言目录必须包含 `frameworks/<language>/README.md`，至少说明：

- `## 常用框架清单`：列出该语言生态中常见框架/库/平台，并标注本仓库已经覆盖的条目。
- `## 选择思路`：说明大型 Web、轻量 API、UI、构建、数据访问、测试等方向如何选型。
- `## 学习路线`：给出建议阅读顺序，先理解语言生态，再进入框架思想和项目结构。
- `## 本仓库案例`：链接到已经实现的框架案例。

## 单个框架 README

每个 `frameworks/<language>/<framework>/README.md` 必须包含：

- `## 核心定位`：框架解决什么问题，不解决什么问题。
- `## 设计思想`：约定、组合、声明式、依赖注入、插件、中间件、响应式等核心思想。
- `## 架构模型`：入口、路由/组件、业务层、配置、依赖、测试的关系。
- `## 请求/执行生命周期`：一次请求、一次渲染、一次构建或一次命令如何流经框架。
- `## 工程结构`：学习案例的目录结构，以及真实项目扩展时的边界。
- `## 配置方式`：配置文件、代码配置、环境变量、构建配置如何协作。
- `## 模块与依赖管理`：框架如何组织组件、服务、模块、包和生命周期。
- `## 数据访问`：默认案例的数据方式，以及接入数据库或外部服务时的常见路径。
- `## 测试方式`：单元、集成、HTTP/UI、构建验证的入口。
- `## 部署方式`：本地运行、打包、容器化或平台部署的基本思路。
- `## 适用场景与取舍`：什么时候优先选它，什么时候考虑其他框架。
- `## 案例索引`：链接到至少一个可运行案例。
- `## 版本来源`：版本基线、策略和官方来源 URL。

## 案例 README

每个 `frameworks/<language>/<framework>/examples/quickstart/README.md` 必须包含：

- `## 目标`：本案例要学会什么。
- `## 学习重点`：把框架思想映射到代码。
- `## 工程结构`：列出关键文件和职责。
- `## 运行前提`：需要的语言运行时、包管理器或 SDK。
- `## 运行`：给出可复制命令；如果本机缺少工具链，脚本可以跳过，但命令必须真实。
- `## 预期输出`：说明启动日志、HTTP 响应、页面行为或测试结果。
- `## 代码讲解`：逐段解释入口、路由/组件、业务逻辑和配置。
- `## 延伸练习`：给出 2-3 个下一步改造方向。
- `## 验收`：学习者完成后应能说明和修改什么。

案例应尽量使用最少依赖，但要保持真实框架结构。对于需要联网安装依赖的生态，仓库中仍应提供源码、依赖声明和运行命令；自动执行脚本默认只做结构验证和 dry run。

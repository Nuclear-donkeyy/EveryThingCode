# 语言特性与思想教学模块规范

本规范用于补充 `languages/<language>/features/`。目标是把“语言思想”和“可运行例子”连起来，让学习者通过运行代码理解语言为什么这样设计。

## 目录结构

每门语言至少包含：

```text
languages/<language>/
  README.md
  features/
    README.md
    examples/
      <topic>/
        README.md
        <source-file>
```

## `features/README.md` 要求

- 标题格式：`# <Language> 特性与思想辅助教学`
- 必须包含以下二级标题：
  - `## 如何使用`
  - `## 思想总览`
  - `## 核心特性地图`
  - `## 教学例子索引`
  - `## 学习检查`
- 至少解释 4 个核心特性或思想，每个特性都要回答：
  - 它解决什么问题。
  - 这门语言为什么用这种方式解决。
  - 学习者应该观察哪个例子。

## 例子要求

- 每门语言至少 3 个教学例子。
- 每个例子目录必须有 `README.md` 和至少 1 个源码文件。
- 每个例子的 `README.md` 必须包含：
  - `## 目标`
  - `## 运行`
  - `## 观察点`
  - 一个 `bash` 代码块，第一条非注释命令必须可以复制运行。
- 例子应优先使用标准库，避免额外依赖。
- 如果某个语言特性通常依赖生态库，先用标准库展示思想，再在说明里指出真实项目会使用哪些库。

## 根 README 链接

每门语言的 `languages/<language>/README.md` 应在案例索引附近链接到：

```markdown
- [特性与思想辅助教学](features/)：通过解释和可运行例子理解语言设计。
```

## 风格

- 中文解释为主，术语第一次出现时可保留英文。
- 不写“因为先进所以好”这类空泛判断，要写具体取舍。
- 例子要短，但不能玩具到看不出思想。

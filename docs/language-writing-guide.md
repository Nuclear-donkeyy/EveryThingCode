# 语言章节写作规范

本规范用于扩写 `languages/<language>/README.md`。目标不是写百科词条，而是帮助学习者快速理解一门语言的设计取向、工程入口和常见误区。

## 内容要求

- 保留统一标题结构：语言定位、适合场景、核心语法、类型/内存/并发模型、标准库与包管理、错误处理、工程化、常见坑、案例索引、版本来源。
- 每个章节都要有实质内容，避免只写一句口号。
- 语言定位要回答三个问题：这门语言为哪些问题而生、它偏好的抽象方式是什么、学习它时最应该改变哪种思维习惯。
- 适合场景可以同时写“不适合场景”，帮助读者形成边界感。
- 核心语法要强调惯用法，而不是机械列语法点。
- 类型/内存/并发模型要把三者拆清楚，避免把并发模型误写成“支持 async”这种单点描述。
- 错误处理要说明错误如何表达、传播、恢复，以及和资源释放的关系。
- 工程化要覆盖包管理、格式化、测试、构建和发布入口。
- 常见坑要写学习者真的容易踩到的坑，并给出修正方向。

## 风格要求

- 使用中文讲解，术语第一次出现时可保留英文原词。
- 保持学习友好，但不要过度口语化。
- 不强行把没有 LTS 概念的语言称为 LTS。
- 不引入未经验证的版本号；版本基线以根目录 `versions.yaml` 为准。
- 不在语言章节加入大型框架教程，框架内容放到 `frameworks/`。

## 完成标准

- 每个语言 README 至少包含 10 个二级标题。
- 每个语言 README 至少包含 1000 个非空白字符。
- 每个语言 README 保留 3 个案例链接：`hello`、`data-flow`、`errors`。
- 每个语言 README 保留官方来源和校验日期。
